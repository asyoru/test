# Игра «Шарики»

Небольшая игра с анимированными шариками: движение, смешивание цветов при касании, всасывание и выпуск шариков мышью, зона удаления.

## Что это за игра и как она работает

- **Окно** — белый фон, в нём движутся цветные шарики с отскоком от границ.
- **Столкновения** — при касании два шарика смешивают цвета (по среднему геометрическому RGB), но не отталкиваются и продолжают движение.
- **Управление мышью**
  - **Зажать ЛКМ** — «всасывание»: шарики в радиусе вокруг курсора притягиваются и при достаточном приближении попадают в инвентарь (исчезают с экрана).
  - **Отпустить ЛКМ** — один шарик из инвентаря «выпускается» в позицию курсора со случайной скоростью.
- **Зона удаления** — розовая полоса внизу экрана; шарики, попавшие в неё, удаляются без возврата в инвентарь.

Стартовое количество шариков и размер окна задаются в начале `game_gui.py`.

## Запуск локально

### Зависимости

- Python 3.9–3.14
- Пакет **pygame-ce** (форк pygame с поддержкой новых версий Python)

### Установка и запуск

```bash
# Клонировать или перейти в каталог проекта
cd /path/to/project

# Установить зависимости
pip install -r requirements.txt

# Запустить игру (одна команда)
python gui.py
```

Альтернативно: `python main.py` или `python game_gui.py` — запустят ту же игру.

## Запуск в Docker (графическое окно через X11)

Сборка и запуск рассчитаны на **Linux с X11** (или WSL2 + X-сервер на Windows). Окно приложения отображается на дисплее хоста.

### 1. Сборка образа

```bash
docker build -t balls-game .
```

### 2. Разрешить контейнеру доступ к X-серверу (только Linux с X11)

Перед первым запуском:

```bash
xhost +local:docker
```

(При необходимости потом можно отозвать: `xhost -local:docker`.)

### 3. Запуск контейнера

```bash
docker run -e DISPLAY=$DISPLAY -v /tmp/.X11-unix:/tmp/.X11-unix --rm balls-game
```

Игра запустится, окно появится на вашем рабочем столе.

- `-e DISPLAY=$DISPLAY` — передаёт переменную дисплея в контейнер.
- `-v /tmp/.X11-unix:/tmp/.X11-unix` — даёт доступ к сокету X11.
- `--rm` — удалить контейнер после закрытия игры.

### Windows (WSL2 + X-сервер)

1. Установите и запустите X-сервер на Windows (например VcXsrv, X410).
2. В WSL2 задайте, например: `export DISPLAY=$(cat /etc/resolv.conf | grep nameserver | awk '{print $2}'):0`.
3. Разрешите доступ: `xhost +local:docker` (если xhost доступен в среде).
4. Соберите образ и запускайте контейнер той же командой `docker run ...` (в WSL2 путь к сокету может отличаться; при необходимости используйте `-e DISPLAY=host.docker.internal:0` и настройки вашего X-сервера для доступа из Docker).

### Если окно не появляется

- Убедитесь, что выполнили `xhost +local:docker`.
- Проверьте, что `echo $DISPLAY` выводит значение (например `:0`).
- На хосте без графики Docker-образ можно собрать, но запуск с окном возможен только при доступном X11 (или аналоге в вашей среде).

## Структура проекта

| Файл          | Назначение |
|---------------|------------|
| `logic.py`    | Логика: классы `Ball`, `GameLogic` — движение, столкновения, смешивание цветов, всасывание, зона удаления. |
| `game_gui.py` | Отрисовка и цикл игры на pygame-ce. |
| `gui.py`      | Точка входа: запуск игры одной командой `python gui.py`. |
| `main.py`     | Альтернативная точка входа. |
| `requirements.txt` | Зависимости (pygame-ce). |
| `Dockerfile`  | Образ для запуска игры в контейнере с выводом в X11. |
